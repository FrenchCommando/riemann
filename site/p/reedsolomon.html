QR codes survive damage: Reed–Solomon codes

Irving Reed and Gustave Solomon, 1960; the QR code: Masahiro Hara, Denso Wave, 1994
Theorem

Encode kkk symbols from a field as the values of a polynomial of degree <k\lt k<k at nnn distinct points. Then any two codewords differ in at least n−k+1n - k + 1n−k+1 places, so up to (n−k)/2(n - k)/2(n−k)/2 wrong symbols can be corrected, or up to n−kn - kn−k missing ones. QR codes do this with bytes, in F256\mathbb F_{256}F256​.

A QR code stores its data as bytes and adds extra bytes so that a scanner can rebuild what a smudge, a tear or a logo destroys. The principle is that a polynomial is pinned down by a few of its values: sample it at more points than needed, and you can afford to lose some.

  1. 1Messages as polynomials

    Turn the message m0,…,mk−1m_0, \dots, m_{k-1}m0​,…,mk−1​ (elements of a field FFF) into m(x)=m0+m1x+⋯+mk−1xk−1m(x) = m_0 + m_1 x + \dots + m_{k-1} x^{k-1}m(x)=m0​+m1​x+⋯+mk−1​xk−1, and send its values m(a1),…,m(an)m(a_1), \dots, m(a_n)m(a1​),…,m(an​) at n≥kn \ge kn≥k distinct points of FFF.

    The kkk coefficients are the information; the other n−kn - kn−k values are redundancy. Any kkk correct values determine mmm (step 4), so the extra values are there to outvote or replace damaged ones.

    More detail

    Over F256\mathbb F_{256}F256​ the symbols are bytes, and there are 256256256 possible points, so a codeword has at most 256256256 bytes. QR codes use n≤255n \le 255n≤255, with the points 1,α,α2,…1, \alpha, \alpha^2, \dots1,α,α2,… given by the primitive element of the previous proof.

    QR encoders actually send the kkk message bytes unchanged, followed by n−kn - kn−k check bytes: the remainder that makes the codeword a multiple of (x−1)(x−α)⋯(x−αn−k−1)(x - 1)(x - \alpha) \cdots (x - \alpha^{n-k-1})(x−1)(x−α)⋯(x−αn−k−1). That form is equivalent to this one (it is the same code up to a change of coordinates, by a discrete Fourier transform over F256\mathbb F_{256}F256​); the version with values is the easiest to reason about.

  2. 2Codewords are far apart

    Different messages give codewords that agree in at most k−1k - 1k−1 of the nnn places. So the code has minimum distance n−k+1n - k + 1n−k+1.

    If m≠m′m \ne m'm=m′, then m−m′m - m'm−m′ is a nonzero polynomial of degree <k\lt k<k, so it has at most k−1k - 1k−1 roots. The codewords agree at aia_iai​ exactly when aia_iai​ is a root of m−m′m - m'm−m′.

    More detail

    So they differ in at least n−(k−1)=n−k+1n - (k - 1) = n - k + 1n−(k−1)=n−k+1 places. That is the best any code can do: the Singleton bound says a code with ∣F∣k|F|^k∣F∣k codewords of length nnn has distance at most n−k+1n - k + 1n−k+1 (delete n−kn - kn−k positions; two codewords must then coincide). Reed–Solomon codes meet it exactly.

  3. 3Correcting errors

    If at most ttt symbols are wrong and 2t≤n−k2t \le n - k2t≤n−k, the codeword nearest to what was received is the one that was sent.

    The sent codeword is within ttt of what was received. Any other codeword within ttt of it would be within 2t≤n−k2t \le n - k2t≤n−k of the sent one, closer than the minimum distance n−k+1n - k + 1n−k+1.

    More detail

    This is the triangle inequality for Hamming distance: d(c,c′)≤d(c,received)+d(received,c′)≤2td(c, c') \le d(c, \text{received}) + d(\text{received}, c') \le 2td(c,c′)≤d(c,received)+d(received,c′)≤2t.

    The statement says the nearest codeword is right, not how to find it quickly; trying all 256k256^k256k messages is hopeless. Scanners use algebra instead: from what was received they compute syndromes (the received word evaluated at 1,α,α2,…1, \alpha, \alpha^2, \dots1,α,α2,…, all zero when nothing is wrong), solve for an error-locator polynomial whose roots mark the bad positions (Berlekamp–Massey), find those roots (Chien search) and compute the corrections (Forney). All of it is arithmetic in F256\mathbb F_{256}F256​.

  4. 4Missing values

    If up to n−kn - kn−k symbols are lost but their positions are known, the message is recovered exactly.

    At least kkk values survive. Two polynomials of degree <k\lt k<k that agree at kkk points are equal (their difference would have kkk roots), so the surviving values determine mmm.

    More detail

    Lagrange interpolation writes the polynomial down. Through points (a1,y1),…,(ak,yk)(a_1, y_1), \dots, (a_k, y_k)(a1​,y1​),…,(ak​,yk​): m(x)=∑i=1kyi∏j≠ix−ajai−aj.m(x) = \sum_{i=1}^k y_i \prod_{j \ne i} \frac{x - a_j}{a_i - a_j}.m(x)=i=1∑k​yi​j=i∏​ai​−aj​x−aj​​. Each product is 111 at aia_iai​ and 000 at the other points. It needs division, which is why the symbols must live in a field.

    Mixed damage works too: eee known erasures and ttt unknown errors can be repaired as long as e+2t≤n−ke + 2t \le n - ke+2t≤n−k.

  5. 5In a real QR codecited

    The codes above are version 3 at level H: 262626 data bytes in two blocks, each with 131313 data bytes and 222222 check bytes. Each block survives 111111 wrong bytes, which is why the sticker doesn't matter.

    QR code specification, ISO/IEC 18004; decoding: Berlekamp, 1968; Massey, 1969; Forney, 1965

    Each block is a Reed–Solomon code with n=35n = 35n=35 and k=13k = 13k=13, so t=(35−13)/2=11t = (35 - 13)/2 = 11t=(35−13)/2=11 by step 3. The four levels L, M, Q and H trade capacity for robustness, repairing roughly 7%7\%7%, 15%15\%15%, 25%25\%25% and 30%30\%30% of the bytes.

    More detail

    How a symbol is laid out:

    • Each byte is placed as a little 2×42 \times 42×4 patch of modules, snaking up and down two-module columns from the bottom right. A smudge therefore ruins whole bytes, which is the unit Reed–Solomon counts.
    • The two blocks are interleaved byte by byte, so a local stain is shared between them rather than overwhelming one.
    • A fixed mask pattern is XORed over the data so that no large blank areas or finder-like shapes appear by accident.
    • The format strip by the corner squares records the level and the mask, protected by its own BCH code (the Frobenius proof shows how that code was designed).

    The sticker here covers a 10×1010 \times 1010×10 patch of modules. It touches 181818 bytes, 888 in one block and 101010 in the other, both within the 111111 a block can repair. At 11×1211 \times 1211×12 modules it would touch 121212 bytes in each block, one more than can be repaired; whether the code still scans then depends on how many of those bytes the sticker happens to leave intact.

Takeaway. A polynomial of degree <k\lt k<k is pinned down by any kkk of its values. Send more values than that, and the extras repair the rest.
