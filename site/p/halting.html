The halting problem is undecidable

Alan Turing, 1936
Theorem

There is no program HHH that, given any program PPP and input xxx, always halts and correctly answers whether PPP halts on xxx.

A hard limit on what computers can ever do, proved before electronic computers existed. It is Cantor's diagonal argument with "programs" in place of "sets".

Builds on Cantor's theorem: no set is as big as its power set.

Walk through it step by step a check at each step, detail adjusted to what you know
Proof · 4 steps
  1. 1Assume a halting decider

    Suppose H(P,x)H(P, x)H(P,x) always halts, returning yes if PPP halts on input xxx and no otherwise.

    Proof by contradiction. Note HHH must answer for every program and input, and must itself always stop.

    More detail

    "Just run PPP on xxx and see" is not a valid HHH: if PPP runs forever, the simulation runs forever and never says no. The question is whether some cleverer program could always answer.

  2. 2Build the contrarian program D

    Define D(P)D(P)D(P): run H(P,P)H(P, P)H(P,P); if it says yes, loop forever; if no, halt.

    DDD is a legitimate program: it calls HHH as a subroutine and then does the opposite of what HHH predicts about PPP run on its own text.

    More detail

    In pseudocode: D(P):if H(P,P)=yes then loop forever, else halt.\textbf{D}(P):\quad \text{if } H(P, P) = \text{yes then loop forever, else halt.}D(P):if H(P,P)=yes then loop forever, else halt. Feeding PPP its own source as input is allowed — programs are just strings. This is the diagonal: we look at the entry "PPP on input PPP" and flip it.

  3. 3Run D on itself

    D(D)D(D)D(D) halts   ⟺  H(D,D)=no  ⟺  D(D)\iff H(D, D) = \text{no} \iff D(D)⟺H(D,D)=no⟺D(D) does not halt. Contradiction.

    The first equivalence is how DDD is built; the second is HHH being correct about DDD on input DDD.

    More detail

    Two cases:

    • If D(D)D(D)D(D) halts, then H(D,D)H(D,D)H(D,D) correctly says yes, so DDD loops forever on DDD. Contradiction.
    • If D(D)D(D)D(D) runs forever, H(D,D)H(D,D)H(D,D) says no, so DDD halts on DDD. Contradiction.

    So HHH cannot exist. ■\blacksquare■

  4. 4Consequences

    Many questions about programs are undecidable.

    If a decider for them existed, you could use it to build HHH.

    More detail

    Reductions: to show a problem is undecidable, show that solving it would solve halting. For example, "does PPP ever print 'hello'?" is undecidable: modify PPP to print 'hello' right before it would halt.

    Rice's theorem generalises this: every non-trivial question about what a program computes is undecidable. That's why perfect virus scanners and perfect bug finders cannot exist — real tools must sometimes say "don't know" or be wrong.

    It also connects to logic: Gödel's incompleteness theorem can be derived from the undecidability of halting.

Takeaway. To rule out a universal decider, build a program that asks the decider about itself and does the opposite.
